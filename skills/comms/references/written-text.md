# Messages, documents, tickets, issues, PRs, commits, and code comments

The round layout is for conversation. Text that leaves the conversation follows these rules
instead, plus the plain-words rules in the main file.

1. Lead with the concrete change or result. Leave out how the session got there.
2. Use the destination's or template's own sections. Glyph labels (❓ ⚠️ ➡️) and finding words stay
   in conversation unless the user asks for them.
3. A code comment names the actual code, constraint, or consequence and says why it exists.
   One short sentence; delete a comment that restates readable code.
4. Before sending, replace these with what the thing is or does, unless one is established
   project vocabulary or the precise technical term: spine, seam, load-bearing, surface area,
   robust, seamless, first-class, guardrail, sharp edge, posture, orchestration, inflection
   point, elegantly, critically, deeply, the real X, X-shaped, X-first. The same check applies
   in conversation.
